# Track 1 게임 디자인

## 한 문장

어디가 막혔는지 눈으로 읽고, 생산·수식 블록을 그쪽으로 옮겨 흐름을 바꾸는 게임.

## 카메라와 시점 기준

카메라와 시점의 family 방향은 B+로 채택됐다. 최종 projection은 `bplus-ortho`·`bplus-balanced`·`bplus-perspective` 중 사람 비교로 정하고, shallow Z 폭과 block visual scale도 별도 tuning gate로 남긴다. 특정 projection이나 크기를 최종 승인으로 취급하지 않으며, 현재 화면의 카메라 각도와 구도는 B+ 비교를 위한 임시 구현이다. 저폴리 3D 그래픽 사용 여부와 projection 선택은 별개의 결정이다.

현재 임시 카메라는 B+ family의 세 projection을 비교하기 위해 플레이어 X축을 제한적으로 추적하고, 플레이어·주변 재료·설비를 공동 프레이밍한다. 이 동작은 비교용 구현이며 세 projection 중 어느 하나의 최종 채택이나 shallow Z·block visual scale 결정을 대신하지 않는다.

## 게임 제목과 온보딩 방향 (확정 방향; 현재 코드 구현·사람 플레이 미검증)

- 현재 사용자-facing 게임 제목은 정확히 `Just Make BREAD!`로 한다. 이전 `Just Make Bread` 표기는 역사적 결정 기록으로만 보존한다.
- 최종 온보딩은 별도의 텍스트 튜토리얼이나 긴 HUD 조작 설명을 사용하지 않는다. 플레이어는 거의 빈 작업장에서 시작하고, 월드 안의 배치·빛·움직임·짧은 상호작용 표시를 통해 다음 행동을 자연스럽게 배운다.
- 공개 순서는 다음과 같다.
  1. 밀 생성원만 먼저 보여 준다.
  2. 고정 `분쇄` 설비와 밀가루 결과를 발견하게 한다.
  3. 고정 `굽기` 설비와 빵 결과를 발견하게 한다.
  4. 제출대를 통해 첫 목표를 완수하게 한다.
  5. 첫 클리어 뒤 `[빠르게!]` 블록을 도입한다.
- 이 흐름은 콘텐츠 해금이면서 텍스트 없는 단계적 학습이다. 긴 HUD 설명을 제거하더라도 다음 행동과 결과가 월드 표현만으로 읽혀야 한다.
- 위 내용은 확정된 방향을 기록한다. Stage 1 P0의 파이프·`분쇄`·`굽기`·제출대 공개 lifecycle은 현재 코드에 구현되었지만 사람 플레이 검증 전이다. 첫 클리어 뒤 `[빠르게!]` 해금과 그 재시작 동작은 아직 구현하지 않았으며, 긴 텍스트 없이 첫 행동부터 첫 클리어까지 읽히는지는 사람 플레이로 검증한다.

## 설계 기준 (최신 게임 방향; Stage 1 P0 구현 규칙과 구분)

게임은 작은 월드에서 실제 자원 토큰과 생산 블록을 사용하는 초단기 생산 퍼즐을 목표로 한다. 현재 Stage 1 P0 활성 경로는 사건 기반 공개 뒤에도 `분쇄`·`굽기` 생산 블록을 Space로 다시 들어 옮길 수 있으며, E 직접 운반과 공간 배치를 함께 사용한다. 아래 규칙은 최신 설계 방향이며 사람 플레이로 승인된 완료 규칙은 아니다.

기본 생산 사슬:

```text
밀 생성 → 밀 집기 → 분쇄 설비에 넣기 → 밀가루 집기 → 굽기 설비에 넣기 → 빵 집기 → 제출대에 넣기
```

- 플레이어는 E를 눌러 월드의 재료를 집고, 호환 설비나 제출대에 직접 넣는다. Space는 생산 블록 집기·내려놓기에 사용한다.
- 플레이어는 한 번에 같은 종류의 재료를 1~5개까지 E로 운반할 수 있다. 한 번의 E는 관찰된 월드 토큰 하나를 추가하며, 다른 종류를 섞거나 5개를 넘길 수 없다.
- M2A 확장 경로에서는 `[분쇄]`와 `[가열]` 생산 블록을 플레이어가 Space로 들고 유효한 월드 위치에 내려놓을 수 있다. 들고 있거나 이동 중인 블록도 자신의 현재 authoritative 위치에서 호환·관찰·반경·용량 규칙에 따라 재료를 예약·흡수하며, 실제 가공 work와 진행 게이지만 정지한다.
- Stage 1 P0에서는 큐브형 `분쇄`·`굽기` 설비가 공개 순서에 따라 나타나고 초기 위치는 서로 분리된다. 공개된 생산 블록은 Space로 잡아 북쪽 벽의 보이지 않는 X-only 논리 제약 안에서 재배치할 수 있으며, pickup 순간이동 없이 block의 실제 허용 X delta만큼 player도 현재 상대 접촉 위치와 player Z를 유지한 채 함께 이동한다. 벽·player·다른 block에서 막히면 둘 다 정지하고, 재료는 E로 직접 운반한다. 기존 자동 흡수 규칙은 이 이동 상태까지 같은 GameState 권위로 적용한다.
- 자동 흡수는 빈 버퍼를 예약한 뒤 일반 world 토큰을 기본 0.12초 간격으로 하나씩 이동시킨다. E로 내려놓은 같은 종류의 held stack은 ordinary world 토큰으로 원자 공개된 뒤 다음 eligible simulation boundary에서 관찰 완료된 호환 토큰을 stable order의 가능한 prefix만큼 한 번에 예약·이동한다. 용량이 부족하면 나머지는 world 상태로 남고, 호환되지 않거나 관찰 전·예약됨·범위 밖인 토큰은 건드리지 않는다.
- 분쇄·굽기는 기능·색상·`분쇄`·`굽기` 라벨로 즉시 구분한다. 내부 생산 타입 `heater`의 명칭과 Stage 1 월드 표기 `굽기`는 구분한다.
- 제출대는 관찰 지연이 끝난 반경 내 빵을 자동 수용할 수 있으며, 멀리 있는 빵은 플레이어가 직접 가져다 넣을 수 있다.
- 토큰은 월드에 실제로 존재하며, 생성원·설비·제출대 사이의 적체 위치가 병목을 보여준다.
- `[빠르게!]`는 이제 독립된 기술 구현 경계에서 E 기반 모듈 상호작용과 명명된 소켓 삽입을 사용하며, 자동 검증은 완료되었지만 사람 플레이·가독성 승인은 pending이다. `[두 배로!]`는 Stage 2에서 물리적 위치와 독립된 10초 충전·4초 active/drain 순환을 기술적으로 구현했으며, active 증폭은 Double이 실제로 붙어 있는 해당 grounded 설비의 qualifying output에만 적용된다. 사람 플레이·가독성·밸런스 승인은 pending이다.
- 제출대에는 빵만 넣을 수 있으며 Stage 0 첫 주문은 빵 1개를 직접 제출해야 클리어된다. 후속 주문의 더 큰 목표는 GameState 옵션과 별도 lifecycle에서 정의한다.

## `[두 배로!]` 배치 가치 (D-5로 대체됨; 역사적 설계 기록)

과거에는 굽기 배치를 즉시 완성품 증폭, 분쇄 배치를 중간재 비축과 후속 연쇄 증폭으로 구분했다. 2026-08-10 D-5가 이 서술을 supersede한다. 선형 생산 사슬에서는 배수 위치 자체가 원리적으로 최종 산출을 바꾸지 않으며, 하류 처리 상한으로 증폭분이 폐기될 때만 차이가 난다. 희소 공급 잠정 시뮬레이션에서는 네 배치 결과가 같았다. 실제 공급·상한·병목 차이는 후속 결정론 시뮬레이션과 사람 플레이로 검증한다.

## 현재 `[두 배로!]` 순환 게이지 규칙 (기술 구현됨·사람 플레이 미검증)

- Stage 2에 정상 admission된 Double은 `world/ejected`, `held`, socket 1, socket 2 어느 위치에서도 같은 GameState 시계를 공유한다. 위치 이동은 충전량·active 잔여시간·phase를 멈추거나 초기화하지 않는다. `locked`는 reset 또는 아직 admission되지 않은 상태만 뜻한다. 이 위치 독립성은 충전/active 시계에 대한 규칙이며 출력 증폭의 전역 권한을 뜻하지 않는다.
- 게이지는 `10초 charging → 4초 active/draining → charging`을 반복한다. 충전 중에는 경과 충전량, active 중에는 남은 drain을 표시하며 active 잔여시간이 0이 되면 root를 숨기거나 제거하지 않고 다음 charging을 시작한다. 고정 step의 active 구간은 `[start, end)`로 정의한다.
- Double의 read-only phase query는 active window만 보고한다. authoritative 생산 완료는 여기에 `status === attached`, 유효한 socket, admitted/grounded block, `attachedToBlockId === productionBlock.id`를 결합한다. 따라서 mill에 붙은 active Double은 mill만, heater에 붙은 active Double은 heater만 atomic pair output을 만들고, world/held 또는 다른 block에 붙은 경우 해당 완료는 단일 output이다. 출력 생성은 Double phase를 소비하지 않으며, 일반 pickup/deposit, score, token, 직접 투입은 Double 증폭 대상이 아니다.
- Main의 authoritative frame delivery는 `0.05초` 이하로 제한되며, 실제 runtime에는 uncapped Double advance caller나 큰 delta 이벤트 계약이 없다. `advanceDoubleModuleState`는 한 호출에서 최대 하나의 phase boundary만 통과하고 그 chronological event를 반환한다. 큰 delta 다중 cycle 동등성 대신 bounded frame partition이 결정론 계약이다.
- Stage 2 wall RESET은 기존 설치·phase를 보존한다. Attempt reset은 current exact-two Q40 visual/request owner와 두 모듈의 identity/status/pose/attachment/root를 유지하고 Fast/Double의 동적 gauge만 canonical initial state로 되돌린다. `stage2-reset-module-spawn` pair resolution/cache는 별도의 새 world publication 경계에서만 비공개 preflight로 동작하며, wall RESET은 이를 재실행하거나 기존 admission을 지우지 않는다. 자연적인 새 Stage2 publication에서는 기존 reversible q40+Double admission transaction이 성공할 때만 Fast/Double의 두 pose와 admission을 함께 publish한다. Factory, q40, receipt, scene, postcondition fault에서는 두 모듈 모두 기존 권위로 rollback하며 fresh receipt/admission/scene을 남기지 않는다. 이 정책은 `max(2 × FLOOR_DROP_MODULE_COLLISION_HALF_EXTENT, 2 × PICKUP_RADIUS) + COLLISION_SEPARATION_EPSILON`에서 최소 안전 간격을 도출하며, dependency-neutral Q40 body authority `0.68m`(half extent `0.34m`)를 공유한다. 이름 있는 anchor-axis 후보를 결정론적으로 검사해 lifecycle token cleanup 이후의 floor/map bounds, current player/reset/button, grounded production block, dock, wheat 제약을 통과한 complete pair만 채택하며, 후보가 없으면 Fast/Double을 함께 fail closed한다. 이 preflight 시점에는 token ledger가 이미 제거되어 dynamic-token 검사는 주장하지 않는다. Stage2로 복귀하는 동안 socketless/one-socket 시각이나 두 모듈의 영구적인 접근 불가를 만들지 않는다. 자동 regression/build 증거는 기술 gate이며 자연 플레이와 최종 visual/feel/balance 승인은 별도 pending이다.

## 플레이어가 읽어야 하는 신호

- 월드에 쌓인 토큰의 위치와 수가 생산 병목을 보여준다.
- 현재 구현에는 화면 고정형 상시 HUD가 없다. 재료·설비·제출대의 상태는 월드 라벨·출력·상호작용 링으로 읽으며, 실패 또는 완료일 때만 최소 결과 피드백을 표시한다. 최종 온보딩에서는 긴 HUD 설명에 의존하지 않고 월드 표현과 짧은 상황별 상호작용 표시가 이 신호를 우선 전달해야 한다.
- 설비의 저장량과 처리 상태는 큐브·처리 링·월드 명칭으로 확인할 수 있다.
- 재료의 색상과 형태를 함께 사용해 밀·밀가루·빵을 구분한다.
- 제출대의 수용 여부는 생산량과 별개의 최종 목표다.

## 현재 코드 기준선 — Stage 1 P0 공개 수직 슬라이스 (구현됨·미검증)

현재 프로토타입은 순수 TypeScript 상태 모델과 Three.js 표현을 분리한 채, 플레이어 전용 시작 상태에서 생산 설비를 사건 순서로 공개한다. 파이프는 1.0초에 공개되고, 밀 생성은 공개 뒤 4.0초 간격으로 시작한다. 공개된 `분쇄`·`굽기`·제출대는 초기에는 서로 분리된 위치에 나타나며, `분쇄`·`굽기` 생산 블록은 Space로 잡아 북쪽 벽의 보이지 않는 X-only 논리 제약에서 재배치할 수 있다. pickup 순간이동 없이 block의 실제 허용 X delta만큼 player가 상대 접촉 위치와 player Z를 유지하며 함께 이동하고, 막히면 둘 다 정지한다. Stage 1의 기본 경로는 플레이어가 E로 재료를 직접 운반하는 것이다. 첫 빵 출력 뒤에는 `빵을 제출하세요`와 제출 수량만 보이는 두 줄 목표 HUD를 표시하고, 그 전에는 숨긴다. 자동 테스트·빌드와 구현자 브라우저 확인은 완료했지만 사람 플레이 승인 전이므로 이 기준선은 `구현됨·미검증`이다.

```text
밀 생성원 공개 → 밀 토큰 → `분쇄` 공개 → 밀가루 토큰 → `굽기` 공개 → 빵 토큰 → 제출대 공개 → 제출대
```

- `wheat`, `flour`, `bread` 토큰이 실제 월드 위치를 가진 컬렉션으로 존재한다.
- 밀 생성원, `분쇄`, `굽기`, 제출대는 넓어진 월드의 분리된 초기 위치에 있다. Stage 1에서는 설비를 옮기지 않으며, 첫 입력 없이 전체 사슬이 자동 연결되지 않는다.
- 밀 생성원은 서쪽 벽 고정부에서 실내 +X 방향으로 곧게 나온 수평 원통형 파이프와 열린 정면 mouth로 표현한다. 결정론적인 `deltaSeconds` 시간 스텝으로 생성된 밀은 mouth 앞에서 짧게 +X 방향으로 방출된 뒤 약 0.55초 동안 바닥 적체 위치로 하강한다. 이 궤적은 표현 계층에만 있으며 활성 밀 토큰 최대량, authoritative 위치·생성 경계·관찰 지연을 바꾸지 않는다. `분쇄`에 넣기 전 밀은 실제 mouth 앞 적체 위치에 누적된다.
- 현재 first-pass 생산 속도 기준은 밀 생성 간격 `1.25초`, 분쇄 기본 처리 `2.40초`, 굽기 기본 처리 `1.65초`다. 자동 흡수 간격 `0.12초`, 토큰 관찰 지연 `0.25초`, 설비 버퍼 최대 `5개`, 활성 밀 최대 `30개`, 출력 튀어나오기 표현 애니메이션 `360ms`는 이 수치 변경과 무관하게 유지한다.
- 플레이어는 E로 `밀 집기 → 분쇄 투입 → 밀가루 집기 → 굽기 투입 → 빵 집기 → 제출대 투입`을 수행할 수 있다. 같은 종류로 든 1~5개 재료는 설비·제출대의 여유만큼 한 번에 투입하고, 남은 재료는 계속 든다. 재료와 생산 블록을 동시에 들지 않는다.
- `분쇄`는 밀만, `굽기`는 밀가루만 받으며 내부 저장량과 예약량의 합은 기본 최대 `5개`다. 호환되지 않는 재료는 자동·수동 모두 투입되지 않는다.
- 자동 흡수 대상은 예약 상태로 월드에 남아 보이고, 예약 토큰은 중복 선택되지 않는다. 예약된 토큰은 기본 0.12초 간격으로 하나씩 버퍼로 이동한다.
- 처리 시간이 지나면 입력 재료가 소비되고, 생산 설비 옆·아래의 얕은 중립 출력 포켓을 기준으로 한 결정론적인 적체 위치에 출력 토큰이 실제 월드에 생성된다. Three.js 표현 계층의 짧은 튀어나오기 애니메이션은 authoritative 위치·처리 시간을 변경하지 않으며, 종료 위치는 실제 토큰 위치와 같다. 출력 토큰은 관찰 지연 전까지 다음 설비나 제출대가 소비하지 않는다.
- 새로 생성·출력된 토큰은 `TOKEN_OBSERVATION_DELAY_SECONDS`(초기값 0.25초) 동안 월드에 머문 뒤 집을 수 있다. 따라서 밀·밀가루·빵의 생성과 적체를 실제 위치에서 관찰할 수 있다.
- 제출대는 공개된 뒤 관찰 지연이 끝난 반경 내 빵을 자동 수용할 수 있고, 플레이어가 들고 와 E로 넣을 수 있다. 실제 표현은 카메라에서 읽히도록 북쪽 벽에 붙은 수납함·밝은 `제출대` 면·어두운 세로 투입구·짧은 선반이며, 바닥 원판은 사용하지 않는다. Stage 0 첫 주문은 빵 1개가 실제 제출되면 완료 상태가 된다. 밀과 밀가루는 제출 수량에 포함되지 않는다.

- `분쇄`·`굽기`와 북쪽 벽 제출대의 공개 표현은 상태 사건 직후 시작하는 600ms 비차단 one-shot settle을 사용한다. 설비 본체·플린스·면 글자와 제출함의 몸체·선반·투입구·라벨만 짧게 정착하고, 바닥 링·출력 포켓·벽 고정부는 고정한다. `prefers-reduced-motion: reduce`에서는 공개 즉시 최종 상태로 표시한다. 이 표현은 authoritative 공개 시점·입력·처리·제출을 지연하지 않는다.
- 이동 입력은 포인터 누름, 포커스 이탈, 문서 숨김, 페이지 이탈, 포인터 취소에서 모든 이동 키와 짧은 탭 측정을 초기화한다. 취소 뒤 repeat keydown은 무시하며, 새 non-repeat keydown에서만 이동을 재개한다. 왼쪽 또는 오른쪽 Shift를 이동 키와 함께 누르는 동안 기존 결정론적 이동 경계에 `PLAYER_RUN_SPEED_MULTIPLIER = 1.5`를 한 번 적용하며, stamina·toggle·FOV·오디오·튜토리얼은 추가하지 않는다. 짧은 W/A/S/D 탭은 이동 키를 처음 누른 순간 Shift 상태를 캡처하고, Shift를 먼저 놓아도 run을 유지하며 이동 키를 먼저 누르면 walk를 유지한다. Rail 블록의 `.18` raw-axis 탭은 Shift와 무관하게 배율을 적용하지 않는다. E·Space 단발 상호작용은 유지한다.
- 현재 맵은 네 방향 경계벽을 가지며, 코드상 임시 카메라는 플레이어를 중심으로 추적하고 대상 변화에 따라 배율을 바꾸지 않는다. 이 동작의 사람 플레이 가독성은 아직 검증되지 않았다.

## Stage 0 첫 주문과 전환 흐름 (확정 방향·미구현)

- 최종 온보딩의 첫 주문은 빵 `1개` 제출이다. 시간 제한과 숨은 시간 감점은 사용하지 않는다. 현재 기본 GameState가 이 1개 target을 사용하며, 더 큰 목표는 후속 주문 옵션으로 분리한다.
- 첫 제출 성공은 completion latch → 기본 점수 1회 확정 → 공정 정지 → 월드 재료·held·버퍼·예약·출력 대기 cleanup → 기존 파이프 퇴장 → `[빠르게!]`와 다음 주문 공개 순서로 진행한다.
- 시간 제한이 있는 후속 주문의 실패는 failure latch 뒤 생산·자동 흡수·출력을 정지하되 실패 상태와 원인을 그대로 보여 준다. 현재 사용자 입력 경로에는 Retry 버튼·`R`·`Enter`가 없으며, wall RESET만 같은 stage를 재시도하는 유일한 gameplay authority다. RESET은 stage-entry 누적 점수로 rollback하고 시계·목표·attempt 재료/버퍼를 정리하지만 block/module/q40 구조와 위치·소유권은 보존한다.
- 같은 simulation tick에 목표 제출과 deadline이 겹치면 deadline 이내 authoritative 제출이 적용된 성공을 우선한다.
- 전환 중 이동 허용·상호작용 잠금은 권장안이지만 미확정이다. 첫 성공 `+100`도 후보 수치이며 authoritative score와 표시 tween을 분리한다. 온라인 leaderboard·Seed는 현재 구현하지 않으며, Hive 실제 연동은 public staging 안정화 뒤 공식 요구·인증·SDK/웹 호환성·개인정보·무로그인 링크·시간 대비 효과를 확인하는 조건부 feasibility spike와 사용자 go/no-go 대상으로 둔다. 결과 계약은 특정 공급자에 종속하지 않는 adapter 경계를 유지하고, 핵심 루프나 무로그인 플레이를 불안정하게 하면 대회 후로 보류한다.
- 구현은 B+ 내부 projection·shallow Z·block visual scale tuning gate 뒤 별도 lifecycle 수직 슬라이스로 진행한다. 자동 테스트나 이 문서 결정만으로 Stage 0 완료 또는 사람 플레이 승인을 선언하지 않는다.

## 수식 블록 방향 (확정 방향·미구현·미검증)

수식 블록 방향은 텍스트 없는 단계적 학습과 실제 병목 선택을 위한 확정 방향으로 기록하지만, 아래 시간·배율·산출 값은 잠정 시뮬레이션 출발점이다. 사람 플레이 후 조정할 수 있으며 acceptance나 자동 회귀 기대값으로 고정하지 않는다.

- `[빠르게!]`는 잠정 `1.8배` 처리 속도의 소모형이다. 실제 처리 중에만 가득 찬 게이지에서 잠정 `8초` 동안 연료가 감소하고, 소진 뒤 잠정 `6초` 정지 후 자동 회복한다. idle에서는 감소하지 않는다.
- `[두 배로!]`는 빈 게이지가 잠정 `10초` 충전된 뒤 잠정 `4초` 발동 창에서 실제 출력 토큰을 두 배로 만드는 축적형이다. Fast의 `full→empty`와 Double의 `empty→full` 게이지 언어는 잠정 `14초` 주기와 반대 위상으로 구분한다.
- `[한 번 더!]` 또는 짧은 라벨 후보 `[또!]`는 Fast/Double을 대상으로 하는 제3 증폭 블록 후보이며 설비가 아니다. `[한 번 더!]+Fast`의 속도 제곱·연료 `1.3배`, `[한 번 더!]+Double`의 `2배→4배`는 모두 후속 잠정안이다. Fast/Double 사람 승인 뒤 M3-V2 이후 별도 마일스톤으로 미룬다.
